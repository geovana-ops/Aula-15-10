ENTENDA O CONCEITO

O que são testes de Back-End?

Os testes de Back-End verificam a parte interna de uma aplicação, incluindo regras de negócio, APIs, banco de dados, autenticação e processamento das informações. O objetivo é descobrir erros antes que eles afetem os usuários.

⚙️

Lógica do sistema

Verifica se as regras e operações funcionam corretamente.

🗄️

Banco de dados

Confere gravação, consulta, atualização e exclusão de dados.

🔐

Segurança

Ajuda a identificar falhas de acesso e proteção das informações.

TÓPICO A

Documentos de Testes

A documentação organiza o planejamento, registra as verificações realizadas e facilita a comunicação dos resultados.

01
📋

Plano de teste

Documento que define o que será testado, os objetivos, os recursos necessários, os responsáveis, os prazos, os riscos e os critérios de aprovação.

Exemplo

Planejar os testes de uma API de cadastro de usuários, incluindo validação de e-mail, senha e duplicidade.

02
🧪

Casos de teste

Descrevem as condições iniciais, os dados utilizados, as etapas de execução e os resultados esperados para verificar uma funcionalidade.

Exemplo

Enviar uma requisição com dados válidos e verificar se o sistema cadastra o usuário corretamente.

03
🚨

Relatório de Incidentes de Testes

Registra problemas encontrados durante os testes, com descrição, gravidade, evidências, ambiente e informações para reproduzir o erro.

Exemplo

A API aceita dois usuários com o mesmo e-mail, contrariando a regra definida para o cadastro.

04
📊

Relatório de Resumo de Teste

Apresenta uma visão geral dos testes realizados, a quantidade aprovada ou reprovada, os incidentes encontrados e a situação da qualidade.

Exemplo

Foram executados 20 testes: 17 aprovados e 3 reprovados. Os resultados indicam que ainda existem falhas a corrigir.

TÓPICO B

Elaboração do Caso de Teste

Conceito

Elaborar um caso de teste significa descrever de forma organizada como uma funcionalidade será verificada. Ele deve indicar o que testar, quais dados utilizar, quais passos executar e qual resultado esperar.

Principais elementos

  • Identificação do caso de teste.
  • Descrição e objetivo.
  • Pré-requisitos e dados de entrada.
  • Passos para execução.
  • Resultado esperado e resultado obtido.
  • Status: aprovado, reprovado ou bloqueado.
EXEMPLO PRÁTICO Caso CT-001

Teste de cadastro de usuário em uma API

Objetivo: verificar se a API cadastra corretamente um usuário com dados válidos.

Pré-requisito: API disponível e ambiente de teste configurado.

Dados de entrada: nome, e-mail exclusivo, senha e perfil permitido.

Etapas de execução

  1. Enviar uma requisição HTTP POST para o endpoint de cadastro.
  2. Informar os dados válidos no corpo da requisição.
  3. Executar a solicitação usando uma ferramenta como Postman.
  4. Verificar o código HTTP e o conteúdo da resposta.
  5. Confirmar se o registro foi criado conforme as regras do sistema.
Resultado esperado

Cadastro realizado, resposta adequada e dados armazenados corretamente.

Critério de aprovação

Todos os resultados observados correspondem aos resultados esperados.

TÓPICO C

Execução do Programa

A execução consiste em realizar os testes planejados e comparar o comportamento real do sistema com o resultado esperado.

▶️

1. Preparar

Configurar o ambiente, os dados e as ferramentas necessárias.

💻

2. Executar

Realizar os passos manualmente ou por meio de testes automatizados.

✔️

3. Registrar

Guardar evidências, respostas, logs e o status de cada teste.

Importante: testes devem ser executados preferencialmente em um ambiente controlado, sem comprometer dados reais ou serviços de produção.
TÓPICO D

Monitoramento e Controle

O monitoramento acompanha o andamento dos testes, enquanto o controle permite corrigir desvios, priorizar problemas e ajustar o planejamento quando necessário.

  • Acompanhar testes concluídos e pendentes.
  • Monitorar erros, logs e consumo de recursos.
  • Verificar prazos e metas estabelecidas.
  • Priorizar incidentes conforme o impacto.
  • Reexecutar testes após as correções.

TÓPICO E

Avaliação de Resultados

Depois da execução, os resultados são analisados para verificar se os requisitos foram atendidos e se existem falhas que precisam ser corrigidas.

📈

Análise dos dados

Comparar os resultados reais com os critérios definidos no planejamento.

🔍

Identificação de falhas

Investigar erros, suas causas e os impactos para os usuários.

🎯

Decisão final

Recomendar correções, novos testes ou liberação conforme os critérios de qualidade.

Por que avaliar os resultados?

A avaliação ajuda a reduzir riscos, aumentar a confiabilidade, melhorar o desempenho e fornecer informações para decisões sobre a qualidade do software.

TÓPICO F

Comunicação com a Equipe de Automação de Testes

A comunicação entre profissionais de QA, desenvolvedores e especialistas em automação é essencial para compartilhar informações, corrigir falhas e manter os testes confiáveis.

Boas práticas de comunicação

  • Descrever os erros de forma clara e objetiva.
  • Compartilhar logs, capturas de tela e evidências.
  • Informar os passos necessários para reproduzir a falha.
  • Definir prioridades e responsáveis pelas correções.
  • Comunicar alterações nos requisitos e nos sistemas.
  • Revisar e compartilhar os resultados após a correção.

Exemplo de comunicação de incidente

Assunto: Falha no teste automatizado de cadastro

Descrição: A API retornou erro ao tentar cadastrar um usuário com dados válidos.

Evidência: Resposta HTTP, horário da execução e trecho relevante do log.

Ação solicitada: Investigar a causa, corrigir o problema e avisar a equipe para repetir os testes.
